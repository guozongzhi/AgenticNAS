# AutoResearcher 工作流手册

这份手册供经验作者、领域专家和平台开发者共用。部门 Wiki 管理经验的正文与修订，AutoResearcher 管理一次研究运行的任务、产物和决策。先按本手册人工跑通一轮，再用同样的输入与出口自动执行。

## 从经验入库到模型验收

~~~mermaid
flowchart TD
    A["提出经验草稿"] --> B{"专家确认适用边界与证据"}
    B -->|缺证据| C["补充验证仿真或外场证据"]
    C --> B
    B -->|通过| D["发布 Wiki 修订并导入快照"]
    D --> E["冻结实验计划、基线和数据划分"]
    E --> F["提交仿真并回收结果"]
    F --> M["构造训练数据并登记版本"]
    M --> G["提交候选训练并回收模型"]
    G --> H{"开发集验证与预算"}
    H -->|需要新工况且有预算| F
    H -->|复用已有证据且有预算| M
    H -->|选定候选| I["锁定候选并执行独立留出评测"]
    H -->|预算内无合格候选| K["归档结果与后续问题"]
    I --> J{"专家复核报告"}
    J -->|达标| L["登记候选模型并回链 Wiki"]
    J -->|未达标或证据不足| K
~~~

草稿阶段的仿真用于补经验条目的证据，由人确认工况与结论。发布后的研究仿真绑定已批准修订，用于本轮实验的数据准备或对照验证。两类仿真均保存来源和产物。

## 操作手册

| 步骤 | 谁触发 | 执行与交付 | 进入下一步的条件 |
| --- | --- | --- | --- |
| 1. 经验入库 | 经验作者、领域专家 | 在 Wiki 填写适用条件、典型及边界案例、证据和验收标准。证据不足时，提交补验证工况 | 专家确认结论及允许用途，发布可定位的修订 |
| 2. 创建研究运行 | 试点负责人 | 导入指定 Wiki 修订。确定研究假设、本轮允许变化的字段、基线、数据划分、指标门槛和预算。生成运行 ID | 确认输入版本、变更范围和预算，建立可复用的基线 |
| 3. 仿真与数据准备 | 编排器或试点操作者 | 提交仿真链路，记录远端任务 ID、工况配置和结果引用。根据预先约定的规则派生训练数据并登记数据版本 | 结果齐全、口径通过检查。训练、开发、留出样本按工况组隔离 |
| 4. 候选训练 | 编排器 | 用固定训练配置提交候选任务，查询状态并回收训练日志、模型产物和实际成本。基线缺少同条件产物时先补跑 | 训练成功且模型可加载。日志、产物与任务能互相定位 |
| 5. 开发集筛选 | 试点操作者，后续可由 Agent 提案 | 查看失败分布，比较候选，记录观察、假设、实际修改与结果。只改训练数据时，从数据准备重跑。确需新工况时，才再提交仿真 | 选定一版候选。预算耗尽且无合格候选时，直接归档 |
| 6. 独立回归 | 独立评测器 | 锁定模型、评测集与评测器版本，用同一留出集和推理条件比较基线及候选。产出整体、分工况和关键误判结果 | 结果齐全，按训练前确定的阈值给出通过、未通过或证据不足 |
| 7. 复核与回写 | 领域专家、模型负责人 | 审定报告。通过后登记模型版本，并在 Wiki 链接报告。知识结论变化时，另起修订并重新验证 | 留存选用或关闭的理由，报告可追溯到原始经验、实验与模型版本 |

**首期谁负责什么**

- 经验作者负责草稿和案例。领域专家确认经验边界、发布修订和复核结论。
- 试点负责人确认可变字段、数据划分、评价门槛和预算。若试点只有一名操作者，也应在运行前分开登记开发集和受控留出集。
- 编排器执行已确认计划、推进依赖、记录状态及成本。Agent 接入后只提结构化计划和修订建议，由编排器验证动作与预算。
- 评测器持有留出集。一次运行选定候选后才执行独立评测。未通过可以登记新假设，但同一留出集的逐例反馈不进入开发循环。若依据盲评结果调整方案，使用此前未曝光的留出工况做下一次独立验收。

## 首轮填写示例

以下为 KB-001 吞吐退化归因试点的运行单样例。尖括号字段需换成真实值，在开始前补齐。

~~~text
经验快照       KB-001 @ <Wiki 已发布修订>
研究假设       增加混合退化反例，能降低小模型将混合场景误判为单一原因的比例
模型对照       基线用原数据配比，候选用同样数量的样本替换部分单一归因样本
唯一变更       训练样本构成
固定项         模型结构、初始化与种子策略、训练配方、样本或 token 预算、推理配置
仿真工况       调度受限、链路恶化、混合退化、信号不足
数据划分       按工况族留出。同一底层工况的变体只进一个集合
运行预算       <仿真任务上限> / <候选训练上限> / <GPU 时> / <墙钟时限>
开发集选型     优先降低混合误判，同时检查总体正确率和补证表现
盲评验收       <混合误判率改善门槛> / <总体正确率下限> / <补证要求> / <时延上限>
证据归档       <Wiki 修订> → <仿真 ID> → <数据版本> → <训练与模型 ID> → <评测报告>
~~~

报告按工况给出评测样本数、基线与候选的计数及比率。若测试集尚未覆盖关键边界，记录缺口并扩大独立验证范围。试点达标只适用于报告覆盖的工况。

## 失败、停止与重跑

| 情况 | 工作流如何处理 |
| --- | --- |
| Wiki 修订未发布或用途不允许训练 | 保留草稿和证据。由专家处理审核或用途，再创建训练运行 |
| 提交超时，远端是否收到未知 | 先按提交标识或远端任务 ID 对账。能确认未接收后再提交。无法确认时标记待对账并暂停下游 |
| 仿真成功但关键结果缺失 | 登记缺失项并暂停下游。补回可追溯产物或重跑该工况。仿真状态或结果接口未接通时，可用经确认的人工回填 |
| 训练失败或模型无法加载 | 保存日志，标记失败，停止该候选的评测。重试使用新尝试记录，保留旧尝试的成本与结果 |
| 用户停止或预算用尽 | 立即停止派发新任务。通过已支持的 MCP 请求停止运行中的任务。能力缺失时继续核对远端状态并记录最终结果 |
| 修订、数据或训练条件改变 | 创建新运行或带版本的新尝试，保留原记录。已出报告持续引用当时的快照 |
| 独立回归未达标 | 归档负结果。模型负责人决定关闭或提出新假设，Wiki 审核人决定是否需要修订经验 |

## 在当前 Demo 里走一遍

进入部门经验库，打开 KB-001 后点击「运行完整流程」。到「实验任务」查看仿真、训练和评测状态，可下载日志或停止当前任务。完成后到「模型评测」查看预设对照结果。也可以点「提交仿真」逐步推进。

Demo 展示的是编排顺序和 UI 操作，使用本地模拟任务与预设分数。真实 Wiki 导入、运行单冻结、候选选择、独立评测和专家回写在接入阶段实现。相关材料见 [工作台 Demo](../../demos/autoresearcher_demo/README.md)、[部门 Wiki 知识库管理模板](WIKI_KNOWLEDGE_BASE_TEMPLATE.md) 和 [平台搭建策略](../design/AUTORESEARCHER_BUILD_STRATEGY.md)。
