# AutoResearcher 平台搭建策略

首期目标是把一条部门经验转成可复核的小模型改进。建议选 AI-RAN 吞吐退化归因做试点，沿用 Demo 的操作路径，依次打通真实 Wiki 修订、仿真证据、训练产物和独立回归评测。

## 当前能力与待确认接口

| 能力 | 当前已知 | 试点需要确认 |
| --- | --- | --- |
| 部门 Wiki | 计划作为经验主库 | 页面修订读取、权限边界、审核状态 |
| 训练 MCP | 已实现提交、停止、状态查询和模型日志下载 | 提交去重、状态映射、模型产物引用 |
| 仿真 MCP | 已实现链路提交 | 是否支持状态查询、停止、结果下载及结构化指标 |
| 工作台 Demo | 浏览、确认及编辑经验，串联模拟任务，下载模拟日志 | 服务端 API 取代浏览器内演示逻辑 |
| 独立评测 | Demo 使用预设分数 | 模型加载、固定评测集、逐例输出 |

假设先在部门内试点，训练和仿真算力继续由现有平台管理。真实工具名、参数和返回字段以 MCP 契约为准。

## 最小架构

~~~text
部门 Wiki ──按修订读取──> 经验快照 ──派生──> 训练集 / 开发集
                               │
工作台 ──> 服务端 API ──> 运行编排器 ──> MCP 适配器 ──> 训练与仿真
                               │                           │
                               └──> 运行状态与事件    <──日志与产物
                                       │
                        版本化模型 ──> 独立评测器 <── 受控留出集
                                       │
                                     验收报告
~~~

- **Wiki 适配器**　首期支持按修订手动导入。保存快照、修订标识、审批状态、允许用途和内容指纹。每个实验都绑定启动时的固定快照。
- **运行编排器**　负责阶段依赖、预算、任务状态、取消与结果回收。先写入任务记录，再调用 MCP。数据库保存状态与事件，支持服务重启恢复。
- **MCP 适配器**　负责参数、状态和错误映射，保留远端任务 ID 与产物引用。仿真能力按真实接口开放，结构化结果暂缺时可先手工导入并登记来源。
- **评测器**　基线和候选使用同一留出集、硬件、推理配置和评测器版本。Agent 迭代使用开发集。最终验收时由独立评测器读取受控留出集。
- **存储与访问**　一个关系库保存索引、任务和事件，沿用部门受控存储保存日志、样本和模型。MCP 凭据留在服务端，产物下载沿用来源权限。

## 最小数据契约

| 记录 | 核心字段 |
| --- | --- |
| 经验快照 | 知识编号、Wiki 修订、内容指纹、审批状态、允许用途 |
| 数据版本 | 数据 ID、版本、来源快照、划分清单、数据指纹 |
| 研究运行 | 运行 ID、研究问题、经验快照、基线、配置版本、预算、启动人 |
| 实验任务 | 任务 ID、运行 ID、阶段、上游任务、提交幂等键、远端 ID、状态、日志和产物引用 |
| 评测报告 | 运行 ID、基线与候选模型版本、评测集及评测器版本、逐例结果、指标和验收结论 |

工作台首期开放导入修订、创建运行、查询状态与事件、请求停止、下载产物，以及按经验修订或模型版本查询报告。

## 建设顺序与验收

| 阶段 | 交付 | 验收 |
| --- | --- | --- |
| 1. 固定试点 | 选一条发布经验、小模型基线、真实工况和独立评测集。人工完成仿真、训练与评测 | 记录输入、任务 ID、日志、模型版本和分数。第二人能按记录复跑 |
| 2. 接入任务 | 部署工作台和服务端，接入 Wiki 修订导入、MCP 和状态库 | 验证提交、状态查询、训练停止与日志下载。按实际端点验收仿真状态与结果 |
| 3. 串联闭环 | 用确定性流程串联仿真、训练和回归，设置任务与时间预算 | 上游失败时下游不启动。服务重启后可恢复。报告能还原各输入与产物版本 |
| 4. 引入 Agent | 在确定性执行器之上引入多轮棘轮循环（`program.md` + `mutable_fields` 白名单 + baseline-first + `keep/discard/crash` + `results.tsv`），按开发集失败提出假设，结束后锁定胜出模型跑唯一一次独立留出评测 | 越界修改被硬拦截；单轮失败/超时记 `crash` 不中断整体探索；按同一预算比较指标、失败率、GPU 和 LLM 成本。由专家决定是否采纳结论 |

第一个实验可固定小模型结构和训练配方，仅改变训练样本覆盖，检验加入混合退化反例能否降低误判。将同源仿真变体按工况分组划分，避免训练集与留出集共享同源案例。借鉴 `karpathy/autoresearch` 时，保留其只读边界、`program.md`、单轮时间帽、Simplicity 偏置与 `results.tsv` 账本，但在远程 MCP 环境下以**声明式白名单配置 + SQLite incumbent 指针**替代自由改代码与 `git reset`，并强制拆出 `dev` 与 `holdout` 评测器防止过拟合。后续做 NAS 时固定训练配方，做 HPO 时固定模型结构，各自维护预算和结果。

## 长任务与异常处理

- 提交超时后按幂等键或远端任务引用对账。远端缺少去重或查询时，把任务标记为待对账，核实后再提交。
- 将远端状态映射为排队、运行、成功、失败、取消中、已取消或待对账。持久化停止请求，收到远端终态后更新。只有成功且所需产物齐全时才启动下游。
- 给运行设置最大任务数、GPU 时与墙钟上限。Agent 运行另外记录模型、提示词版本、调用成本和终止原因。
- 接入验收涵盖重启、轮询中断、停止与完成竞态、产物缺失。持续观察等待时长、成功率、取消延迟和待对账任务数。
- 首期可在一个服务内运行定期扫描的任务执行器。并发增长后再拆分执行进程。跨组维护成规模时再引入批量同步、复审和全文检索。

## 首个试点完成定义

在同一盲评集上比较基线与候选，报告归因正确率、关键误判率、证据不足时的补证表现和推理成本。验收门槛在训练前冻结。每份报告均可追溯 Wiki 已发布修订、训练数据与配置、仿真证据、训练日志、模型产物和评测版本。由领域专家决定是否将验证结论写回 Wiki。
