## 本次新增解析（2 篇）

1. [TacEvo: Self-Evolving Architecture Discovery for Robotic Tactile Perception via LLM-Driven Quality-Diversity Search](https://arxiv.org/abs/2606.30109)（2026, arXiv）
   - 新建：[结构化解析](../papers/parsed/2026-arxiv-tacevo.md)；论文直接链接的 [代码仓库](https://github.com/LannWei/TacEvo) 可访问。
   - Claude 3 Haiku 对真实 CNN 代码做 mutation/crossover；候选须通过语法、实例化和 forward/backward 验证，再以 10-epoch validation loss 进入 CVT MAP-Elites。
   - 每任务 20 代、每代最多 50 proposals；作者报告 96.0%/94.5% 可训练率和 88.0%/92.0% archive coverage，并对 top variants 做 20-seed 重训。
   - 关键限制：只有一次 search trajectory，没有 matched-budget random/evolution/QD 消融；未报告硬件、GPU-hours、LLM token/费用和完整高保真 recipe。Efficiency Ratio 是 descriptor，不是 latency/memory Pareto 目标。

2. [RZ-NAS: Enhancing LLM-guided Neural Architecture Search via Reflective Zero-Cost Strategy](https://proceedings.mlr.press/v267/ji25a.html)（2025, ICML）
   - 新建：[结构化解析](../papers/parsed/2025-icml-rz-nas.md)；PMLR 正式页面、PDF 和 [Software](https://github.com/PasaLab/RZ-NAS) 已核验。
   - GPT-4o 在 NAS-Bench-201/DARTS micro cell 与 MobileNet macro backbone 中生成变异；zero-cost score 由代码计算，并把 score/exception 送入 reflection。
   - 每 proxy × search space 为 1,500 iterations；作者报告每轮约 2,300–2,600 input、150–200 output tokens，每 proxy 约 75 美元。
   - 关键限制：最终选择依赖 zero-cost proxy，表中的基线并非统一候选、LLM token、训练 recipe 与 GPU 预算；FLOPs 约束也不等于真实设备 latency/memory。

## 重点结论与后续问题

- **把合法性和多样性拆开测。** TacEvo 的 validation gate 对 action validity 有直接价值，CVT archive 对 coverage 有价值；但两者和 LLM 本身需用 matched-budget ablation 分离，不能只看单次搜索轨迹。
- **反思 payload 应是窄接口。** RZ-NAS 的 `parent + score + exception` 很适合 memory-aware policy；本仓库应使用可审计 schema/error code，不能传递内部代码、端点或日志。
- **QD descriptor 不等于 Pareto objective。** TacEvo 的 Efficiency Ratio 及 RZ-NAS 的 FLOPs/proxy 都不是实测 latency/memory/energy。最终仍需真实设备上的 quality/latency/memory/cost Pareto 与 hypervolume。
- **预算公平仍是主缺口。** 后续协议统一 attempted candidates、失败计数、训练 steps、GPU-hours、LLM calls/tokens/费用和至少三组 search seeds；top-k 再以相同完整训练和设备测量复核。
- **下一轮优先级。** 优先解析 feedback-memory 或 progressive-knowledge 候选，并复现 TacEvo/RZ-NAS 的最小公开流程；同时继续监控 arXiv 新提交。
- `quality_proxy` 与 `latency_proxy_ms` 继续只作为控制流占位符；本日报没有把 zero-cost proxy、validation loss 或 descriptor 当作本仓库真实研究结论。
