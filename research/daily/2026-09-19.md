## 本次新增解析（2 篇）

### 1. LLM-Driven Composite Neural Architecture Search for Multi-Source RL State Encoding（LACER）

- 来源：[arXiv:2512.06982v2](https://arxiv.org/abs/2512.06982)、[OpenReview](https://openreview.net/forum?id=cjeisJBijK)、[作者主页](https://qianjanexie.github.io/)；NeurIPS 2025 LAW Workshop。
- 收录原因：LLM 真实决定 time/traffic/sequence/fusion encoder 的 heads、width、ratio、depth 等结构字段，并通过候选 RL 训练结果闭环更新；不是 Agent workflow 搜索。
- 主要证据：每法 50 evaluated candidates、每候选 200k PPO train + 50k evaluation、8 seeds；两条 LACER 曲线在 Fig. 2 高于 expert、DARTS、ENAS、PEPNAS 和 GENIUS。
- 关键限制：主实验先在同任务上挑选 Claude Sonnet 4.0/temperature 1.0，GENIUS 却使用 GPT-4；没有显著性检验、作者代码、完整 prompt/失败记账或 tokens/GPU-hours。论文称约 2600 万空间，但 Table 1 直接 Cartesian product 为 43,046,721，需澄清额外约束。
- 与当前方向：typed composite modules 和中间表示反馈值得复现；单模块 depth 仅 1–3、无 Conv1d/设备 Pareto，不能直接支撑 4–10 层 Conv1d Transformer 结论。

### 2. Bayesian Optimization with Rich Auxiliary Information via LLMs

- 来源：[arXiv:2609.19437v1](https://arxiv.org/abs/2609.19437)，2026-09-16 提交、2026-09-18 公告。
- 收录原因：这是新的 LLM-guided BO/HPO 邻接方法，用 LLM 生成 GP function/argmax prior，并把训练统计作为 auxiliary observations；但 MLP 示例搜索 `n_units_1/2`，故归入 `mixed-search-space` 而非严格固定架构 HPO。
- 主要证据：HPOBench 的四个展示面板使用 3 个 warm-start points、最多 30 evaluations、100 seeds；两种 prior-augmented BO 曲线最强。Auxiliary feedback 另在 50-seed HPO 与 20-seed/250-evaluation DIII-D 图中改善 LLM-guided optimizer。
- 关键限制：未披露 base LLM、temperature、prior query counts、`N/n/beta/sigma`、tokens/费用与代码；只给选择性曲线而非完整 5×5 任务表。Appendix prompt 写 held-out test F1，主文 objective 为 validation F1，需修正为 validation-only。
- 与当前方向：更支持“LLM 作为可衰减先验，GP/BO 保留不确定性”，不支持 LLM 独立替代 surrogate；硬件与 Pareto 证据为空。

## 已筛选、暂不入库

- [Evolution or Illusion? Rethinking Evaluation in LLM Evolutionary Search](https://arxiv.org/abs/2609.19799) 对三种 LLM evolutionary program-search 策略做 seeds × iterations frontier，证明方法排名会随宽度/深度预算改变。它不搜索神经架构，因此不进入论文索引，但其 matched-total-budget 报告协议应加入 AgenticNAS 搜索实验。
- [Portfolio-Based Constrained Multi-Objective Bayesian Optimization for Materials Design](https://arxiv.org/abs/2609.19550) 用 LLM multi-agent 在 acquisition portfolio 中切换并评估 feasible hypervolume；搜索对象是材料实验决策，不是神经架构/HPO，只作为 Pareto controller 邻接参考。
- `2609.12455` SAGE-Loop 搜索 tabular model/feature/HPO/ensemble pipeline，不是稳定神经架构对象；`2609.12418` RiPPLE 与 `2609.14184` ZAPS 是非 LLM NAS；`2609.13945` SAILOR、`2609.16846` LLMDE 与其他 optimization 论文没有真实神经架构目标。
- 本轮仍未发现直接针对 4–10 层 Conv1d Transformer、同时把真实 latency/peak memory/energy 纳入 LLM Agent 闭环的新 Pareto 论文。

## 重点结论与后续问题

- **复合结构反馈值得做严格同模型消融。** LACER 的候选数与 seed 设计较好，但 base LLM 不一致；下一步必须让 metric-only 与 richer-feedback 使用同一模型、temperature、attempted/evaluated budget。
- **LLM 更适合提供先验，而不是直接替代 optimizer。** `2609.19437` 的图示支持 GP/BO 吸收 LLM 先验并随数据衰减；复现必须公开 prior query cost 和所有关键超参。
- **搜索预算需要二维报告。** `2609.19799` 提醒同一总 LLM budget 下 seeds（宽度）和 iterations（深度）的分配会改变方法排名；未来日报所引实验不应只报单一轨迹。
- **数据边界必须 validation-only。** LLM prompt、搜索 archive 和 device feedback 均不得包含 test score；最终 test 仅在选定架构上一次确认。
- **目标设备证据仍缺失。** 两篇新增论文都没有真实 latency、peak memory、energy 或部署正确性 gate；`quality_proxy` 和 `latency_proxy_ms` 继续只能作为流程占位符。
- **下一轮优先级。** 检查下一次 arXiv 公告；寻找可公开复现的 composite NAS/LACER 后续代码；跟踪 `2609.19437` 的代码与模型配置；继续搜索 Conv1d Transformer 和真实设备 Pareto。
