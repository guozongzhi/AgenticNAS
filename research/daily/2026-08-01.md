## 本次新增解析（2 篇）

1. [Resource-Efficient Iterative LLM-Based NAS with Feedback Memory](https://arxiv.org/abs/2603.12091)（2026, arXiv）
   - 新建：[结构化解析](../papers/parsed/2026-arxiv-feedback-memory-nas.md)；论文脚注链接的 [匿名代码快照](https://anonymous.4open.science/r/Iterative-LLM-Based-NAS-with-Feedback-Memory-E7D6/) 可访问。
   - 冻结的代码 LLM 生成完整 PyTorch CNN，Prompt Improver 维护最近 5 次问题—建议—结果/错误三元组；每个合法候选只训练 1 epoch。
   - DeepSeek/Qwen 各做 2,000 iterations，GLM-5 只做 100；一次 2,000-iteration search 约 18 RTX 4090 GPU-hours，但论文未给完整两角色 LLM calls/tokens/费用。
   - 关键限制：baseline 主要是首次成功生成，缺少 matched-budget evolution/stateless LLM 与多 search seeds；top candidates 未完整训练；validation/test 指标表述不一致，需核对 test-feedback leakage。

2. [Structured Progressive Knowledge Activation for LLM-Driven Neural Architecture Search](https://arxiv.org/abs/2605.04057)（2026, ICML 2026 claim / arXiv）
   - 新建：[结构化解析](../papers/parsed/2026-icml-spark.md)；[公开代码仓库](https://github.com/AIM-ResearchLab/SPARK) 可访问。PDF/仓库声明 ICML 2026，官方 PMLR 页面尚未核验，故不把 venue 写成已正式确认。
   - ASR 先选 OPERATOR/ACTION，RC 生成域内 directive，SAR 只在所选区域修改；跨域、syntax/interface/shape 失败 proposal 在训练前拒绝。
   - 主 DFS search 固定 100 proposal attempts；与相同 backbone/editor/evaluator 的 OpenEvolve 对照显示更高 valid rate 与 best-so-far，附录给出 SPARK 五 seed trajectory。
   - 关键限制：28.1× 是 EvoPrompting 1,600 evaluations 除以 SPARK 57 evaluated candidates，并未统一 proposal、每轮多 role LLM calls、GPU-hours 和训练成本；没有真实 latency/memory Pareto。

## 重点结论与后续问题

- **memory 必须和“多尝试 + 保留 best”拆开。** Feedback Memory 的 `K=5` 诊断三元组值得复现，但当前 single-shot baseline 太弱；应加入 stateless iterative LLM、best-only、success-only、success+failure 和 native evolution 的等预算对照。
- **先选 scope 再发 action 是强接口。** SPARK 的 OPERATOR/ACTION 可映射为本仓库 `block/cell/op/connectivity`，Agent 只输出 typed mutation，本地 validator 负责构造与执行，避免 arbitrary code 和 clean-room 越界。
- **主预算用 attempted candidates。** 非法 proposal 仍消耗 LLM calls 和 wall time；不能只用 evaluated candidates 得出加速。每轮多 role calls 还需单独统计 tokens、费用与失败重试。
- **代理和硬件主张都需收紧。** 一 epoch accuracy 不是完整训练质量，共享 RTX 4090 VRAM 也不是 hardware-aware objective；MACs 不能替代真实 latency、peak memory、energy 或 Pareto hypervolume。
- **数据隔离要进入 validator。** Feedback Memory 论文对 validation/test 的表述不一致；本仓库 search 只能看 train/validation，test 必须在最终冻结后一次性评估。
- **下一轮优先级。** 解析 Delta-Based NAS 与 LLM-as-Tool tree NAS，继续监控 arXiv 新提交，并尝试对 SPARK/Feedback Memory 公开代码做最小依赖与 trace 审计。
- `quality_proxy` 与 `latency_proxy_ms` 继续只作为控制流占位符；本日报没有把单 epoch accuracy、MACs 或共享显存当作本仓库真实研究结果。
