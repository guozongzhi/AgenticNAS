## 本次新增解析（2 篇）

1. [Enhancing LLM-Based Neural Network Generation: Few-Shot Prompting and Efficient Validation for Automated Architecture Design](https://arxiv.org/abs/2512.24120)（arXiv v2）
   - 新建：[结构化解析](../papers/parsed/2025-arxiv-few-shot-prompting-nas.md)；公开 [NN-GPT](https://github.com/ABrain-One/NN-GPT) 与 [NN-Dataset/LEMUR](https://github.com/ABrain-One/NN-Dataset)。
   - 在固定 DeepSeek Coder 7B、单次 code generation 与 1-epoch SGD proxy 下，改变 prompt 中 supporting architectures 数量 n=1..6；这是 prompt/context 消融，不是多轮 Agent feedback loop。
   - Table 1 的 n=1..5 训练候选数为 1,268/306/103/102/121；n=3 balanced mean 为 53.1%，n=1 为 51.5%，两者 95% CI 重叠。显著正结果主要是 CIFAR-100 的 26.1% 对 14.5%（p=0.001，d=0.73）；CelebA、CIFAR-10、ImageNette、SVHN 的最佳 n 并不统一。
   - n=6 报告 7 valid / 3,394 queries；必须把 attempted、valid、unique、trained 分层，而不能只比较成功候选。论文的 1,900 trained、4,033 hash samples 与 3,394 n=6 queries 也没有完整统一到账。
   - artifact 可访问但未冻结 paper commit。2026-09-11 的 NN-GPT HEAD 为 `904437058a274f3d25840017094789af58ee2590`，NN-Dataset HEAD 为 `fc9c0e3681d5fe84d15bc3ffc579e9de122b4b8f`；当前默认模型/temperature 已与论文漂移，且当前 NN-GPT 树未定位到所述 whitespace-normalized MD5 实现。

2. [LLM-Driven AutoML for Cross-Lingual Handwritten OCR: Closed-Loop Neural Architecture Search with GPT-5, GPT-4o, and Claude Sonnet 4](https://arxiv.org/abs/2607.15509)（ICCKE 2025）
   - 新建：[结构化解析](../papers/parsed/2025-iccke-llm-ocr-automl.md)；accepted manuscript 与 Crossref 均核验 DOI [10.1109/ICCKE68588.2025.11273810](https://doi.org/10.1109/ICCKE68588.2025.11273810)。未发现作者代码。
   - GPT-5、GPT-4o、Claude Sonnet 4 分别输出 CNN/可选视觉 Transformer 与 optimizer/lr/batch/epoch 等联合配置；每个 LLM × Arabic/Persian/English 各 30 轮，共 270 个候选训练，因此归为 `mixed-search-space`。
   - 作者报告各组合 mean test accuracy 0.921–0.959、best 0.944–0.981、0.88–9.28M mean parameters、batch-1 FP32 NVIDIA GPU latency 40.6–43.8 ms。
   - 每轮把 train/validation/test accuracy 反馈给下一轮；这是 adaptive test reuse。论文没有 matched-budget NAS/HPO 基线、no-feedback 消融、搜索空间边界、代码、GPU 型号、LLM calls/tokens 或总 GPU-hours，headline test 与 latency 不能作为无泄漏泛化或设备 Pareto 证据。

## 已筛选、暂不入库

- [Efficient Leakage-Free Neural Architecture Search under Leave-One-Subject-Out Evaluation](https://arxiv.org/abs/2609.09433) 是 2026-09-10 最新 NAS 新稿，但使用分块/共享传统 NAS 评估降低 LOSO 成本，没有 LLM/Agent proposal loop；保留为数据泄漏评估的邻接方法，不纳入 LLM-NAS 主线。
- [LM-Searcher](https://arxiv.org/abs/2509.05657)（`2509.05657v3`）用统一数值编码和 instruction-tuned LLM 对 candidate pool 排序，作者代码可访问；相关性高，下一轮应解析其跨 CNN/LoRA 搜索空间、pruning subspace 构建和 matched-budget 公平性。
- [Closed-Loop LLM Discovery of Non-Standard Channel Priors in Vision Models](https://arxiv.org/abs/2601.08517) 有公开 NN-GPT/NN-Dataset 产物，但当前优先完成上次指定的 OCR 与 few-shot 缺口；后续需核对 AST seed population、proxy-to-full 排序与 channel-only 变量控制。

- 9 月最新列表中的 systems-engineering “architecture modelling”论文搜索的是系统模型，不是真实神经网络架构；排除。
- 本轮仍未发现直接针对 4–10 层 Conv1d Transformer 的新 LLM/Agent NAS 或固定架构 LLM-guided HPO 论文。

## 重点结论与后续问题

- **prompt 数量必须与有效预算一起审计。** Few-Shot/LEMUR 的 n 增大既改变早期 accuracy，也大幅改变生成有效率；公平比较应固定 attempted calls/tokens，另报 conditional-on-valid 指标。
- **1-epoch proxy 不能替代完整训练。** n=3 的正结果主要集中在 CIFAR-100，且没有 multi-epoch 排序或 proxy reliability；需要冻结相同数量候选再做完整训练。
- **test 不能进入 proposal feedback。** OCR AutoML 的闭环把 test accuracy 当历史信号，最终 test 不再独立；复现必须只用 validation，test 在搜索结束后一次评估。
- **architecture 与 HPO 要正交。** OCR 论文同时改变层结构、optimizer、lr、batch 与 epoch；需分别做 architecture-only、HPO-only、joint 三组，才能解释贡献。
- **代码公开不等于 paper-reproducible。** Few-Shot 的代码/数据仓库持续更新，默认模型/temperature 已漂移；下一步应取得 paper commit、生成 manifest、seed 和阶段化失败账。
- **去重应分层。** whitespace hash 可作为便宜 exact-format gate，但 Python whitespace 有语义且无法识别图同构；应追加 AST/typed-graph signature 与人工误差审计。
- **与当前空间的直接映射。** supporting-example count、typed parser 与 validity accounting 可迁移到 4–10 层 Conv1d Transformer；两篇视觉论文的 accuracy/latency 数值不可迁移。
- `quality_proxy` 与 `latency_proxy_ms` 继续只能作流程占位符；本轮没有证据允许把它们写成研究结果。
- **下一轮优先级。** 解析 LM-Searcher，再审计 Closed-Loop Channel Priors；并尝试定位 Few-Shot 的 paper commit/hash 实现与 OCR 作者代码/完整 prompts。
