## 新增解析（5 篇）

### LLM × NAS：2 篇

1. **AutoBCI**（`2609.35456v1`）：六个 LLM 各 6×8 proposal，总请求 288，269 个架构完成三任务并进入 pool；807 个 full task runs、32,280 task-epochs、68.58 GPU job-hours。PEEK 以 epoch-10 曲线预测 40-epoch 结果，retrospective 策略估计节省 44.9% GPU job-hours；但 19 个缺失候选没有按 invalid/OOM/divergence/duplicate 拆账，主候选只用 seed 0，真实设备指标与总代价未报告（PDF pp.3–10、15–16、20–22）。
2. **OpenArchEvo**（`2609.40258v1`）：开放式 SNN code/rationale archive + 21D fingerprint + TabPFN surrogate + novelty/island selection。151 个新架构折算 3,171 V100 GPU-hours；约 49% acceptance，每轮超过 2,000 次 LLM calls，但 token/USD/墙钟未报告。主搜索只有 1 run，且 ListOps 搜索直接使用 test split；能耗为 SOP/MAC 算术估计而非真机测量（PDF pp.5–11、19–25、28–29）。

### 固定架构 HPO：0 篇

- 没有新增同时满足“架构、数据与 evaluator 固定，只改变 training recipe，并与 random/TPE/CMA-ES/pure LLM/hybrid 做可审计 attempted-trial 预算比较”的论文。

### mixed-search-space：1 篇

3. **PINNMorph**（`2609.32685v1`）：在线演化声明式 adaptation policy，同时改变 topology、loss、sampling、gradient 和 optimizer，因此不是纯 NAS/HPO。13 PDE×5 seeds、20k steps；full method 报 38 LLM calls、4.40e5 tokens、1308s，但硬件、USD、invalid/rollback/duplicate 分母未报告，相同 optimizer steps 也不等于 GPU 预算匹配（PDF pp.3–11、15–18）。

### 相邻 Agentic BO：1 篇

4. **HERA**（`2609.34281v1`）：LLM 控制五类高维 BO backend 的选择、重构和重启，PRISM 生成合法非重复候选。12 tasks、每 task 100 evaluations（含 5 shared Sobol）、10 seeds；它在 real-world tasks 对 strongest classical baseline 报 6/8 最佳 mean，但任务包含控制/芯片/分子等通用黑箱，不是固定架构 ML HPO。HERA tokens 最高、cache hit 94%，USD/墙钟/计算成本未报告（PDF pp.3–13、17–22）。

### 传统 NAS 邻接基线：1 篇

5. **LESS**（`2610.01468v1`）：CMA-ES 离散 cell search + candidate-conditioned calibration；25 warmup +60 search epochs，每 epoch 12 proposals+incumbent，即 780 evaluations/run。NB201 使用 24 paired CIFAR-10 seeds、另两数据集各 8 seeds，单 RTX 4090 搜索约 409–453 秒；K6 对 selected validation 改善 0.577pp，但 best-visited 仅 0.054pp，说明主要收益来自选择校准。DARTS 600-epoch retraining 未计入 search cost，代码链接当前不可访问（PDF pp.4–11、16–24）。

## 重点结论与下一轮

- AutoBCI 提供较完整的 candidate/training/token 账本，但仍需把 288→269 的损失、重复和 seed variance 补齐；其 PEEK 是可迁移的多保真选择器，不是独立 memory policy 证据。
- OpenArchEvo 的 archive/novelty/duplicate screening 对 memory-aware NAS 有启发，但 test-feedback 和单 search run 是关键风险；估算能耗不能替代真实硬件 Pareto。
- HERA 支持“LLM strategy controller + classical backend + shared observation memory”，但只能作为通用 Agentic BO 邻接证据；PINNMorph 必须拆分 architecture/recipe 轴；LESS 可作为 calibration、公平候选评估与 bounded retry 的传统 baseline。
- 下一轮优先：跟踪 EvoTreeNAD、AutoBCI、OpenArchEvo、HERA、LESS 官方代码/trajectory；轮换回看固定架构 HPO 与 real-device multi-objective NAS；继续寻找 Conv1d Transformer、action validity、duplication、attempted trials 和完整成本组合。
