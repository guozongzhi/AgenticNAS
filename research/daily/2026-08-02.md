## 本次新增解析（2 篇）

1. [Delta-Based Neural Architecture Search: LLM Fine-Tuning via Code Diffs](https://arxiv.org/abs/2605.04903)（2026, arXiv）
   - 新建：[结构化解析](../papers/parsed/2026-arxiv-delta-nas.md)；[代码](https://github.com/ABrain-One/nn-gpt)、三种公开模型和 197 个已合并候选架构 artifact 可访问。
   - 三种 7B LLM 对 LEMUR 中的工作 CNN 生成 unified diff；候选依次经过 patch、语法、实例化、forward、单 epoch accuracy 与 MinHash novelty gate。
   - 每个 LLM 22 cycles × 50 = 1,100 candidates；作者报告 valid rate 75.3%/72.1%/66.6%，输出约 30.4/31.4/49.5 lines，完整三 LLM 研究约 90–100 GPU-hours。
   - 关键限制：full-generation baseline 的训练 corpus/数据覆盖不同；只有一个 search seed；headline quality 是一 epoch proxy，DeepSeek top set 的 50-epoch秩相关不显著；没有真实 latency/memory Pareto。

2. [LLM as a Tool, Not an Agent: Code-Mined Tree Transformations for Neural Architecture Search](https://arxiv.org/abs/2604.16555)（2026, arXiv）
   - 新建：[结构化解析](../papers/parsed/2026-arxiv-llmastool.md)；正文未给作者代码，GitHub 精确检索也未找到公开实现。
   - 规则算法从 PyTorch/MMCV/MMPretrain/timm 源码挖取 modules，把网络表示成层次树；高层 operation/category 由 epsilon-greedy hierarchical Thompson sampling 决定，Qwen3-8B 只补齐最后的 transformation 细节。
   - NAS-Bench-201 搜索 100/500 new architectures；ImageNet-100 主消融搜索 100 architectures。作者报告 tree transformation、module mining、coarse-to-fine 和 hierarchical sampling 的逐步收益。
   - 关键限制：没有公开代码、GPU 型号/GPU-hours、LLM calls/tokens/费用和完整失败账；FLOPs/parameter 只是约束，不是实测 latency/memory/energy。

## 重点结论与后续问题

- **动作表示应继续从 code diff 收窄为 typed action。** Delta-NAS 说明局部 patch 可减少输出，但 arbitrary diff 仍有 context/shape failures；本仓库更适合 `block/cell/op/connectivity` schema + 本地 builder。
- **树层次是 block/cell/op 的直接桥梁。** LLMasTool 的 operation→category→location/module→parameters coarse-to-fine loop 可转成有限动作枚举，LLM 只处理最后的合法自由度。
- **表示收益必须与语料收益分开。** Delta-NAS 的六数据集 corpus 与 CIFAR-10 full-generation baseline 混杂；最小复现需同 corpus、同模型、同 candidates 比较 full code、diff 和 typed action。
- **主预算仍用 attempted candidates。** patch/feasibility 失败照样消耗 LLM calls 和 wall time；两篇都缺少完整失败、tokens、费用和多 search seed 对账。
- **proxy 与 FLOPs 不能代替设备目标。** 一 epoch accuracy、output lines、FLOPs、parameter constraints 都不是实测 latency、peak memory、energy 或 Pareto hypervolume。
- **下一轮优先级。** 核对 convergence-theory 候选与 OrchNAS 的真实 energy/memory measurement；同时继续监控 arXiv 新提交，并尝试锁定 Delta-NAS 代码 commit 做最小 trace audit。
- `quality_proxy` 与 `latency_proxy_ms` 继续只作为控制流占位符；本日报没有把论文 proxy、FLOPs 或 token reduction 当作本仓库研究结果。
