## 新增解析与准确分类

1. **Agent Stack for ML Training Lifecycle**（`2611.00384v1`）—`mixed-search-space / MLE Agent`：AutoResearch 同时改 architecture、training configuration 与代码，在固定 incumbent 上同步并行 trials；外部 orchestrator 保存 memory、budget 与 failures。作者报告 100 条 production pipeline 中 28 条最终 held-out 改善，但缺逐任务 attempted/failed、GPU、LLM 调用和 matched classical baseline，不能当独立 NAS/HPO 证据。
2. **MCUFlowNet**（`2611.08147v1`）—`传统 hardware-aware NAS`：macro 设计固定 peak SRAM，micro search 用 NSGA-II 评 800/23,328 subnets 的 EPE–latency Pareto。最终 Ethos-U55 board latency 实测，MCUFlowNet-S 为 93.2 ms/1170 KiB；search latency/SRAM 仍由 Vela 估计，energy 和完整 host cost 缺失。
3. **AutoCompress**（`2611.08290v1`）—`传统 differentiable hardware-aware NAS`：搜索 global/per-layer widths、heads、experts 与 layer removal；被压缩对象是 LLM，但 proposer 不是 LLM Agent。RTX 5070/5080 的 latency+memory 和 H100 throughput 在真实 GPU 上验证；B200 case 用 128 GPUs×约 64 h，缺多 search seeds、energy 与完整失败账本。
4. **LLINBO v3**（`2505.14756v3`）—`Agentic BO 邻接`：用 GP uncertainty 对 LLM proposals 做接受/拒绝/退回 classical BO，并给 no-harm regret guarantee。新增真实 3D 打印实验每方法只有一条 10-evaluation trajectory，不能作为统计胜出或 fixed-HPO 证据。
5. **Physical Agentic Optimization Testbed**（`2611.11690v1`）—`Agentic BO 邻接`：3 个 target 各做一次 BO/Claude Opus 5 physical campaign，每次 48 experiments、约 4 h；Agent 达标 iterations 为 10/23/11，BO 为 21/34/>48，三条 Agent campaign API 共 `$20.83`。方法×target 单次配对且 Agent 可换模型，不能分离 LLM 与 optimizer 设计贡献。
