## 本次新增解析（3 篇）

1. [Agentic Neural Architecture Search](https://arxiv.org/abs/2607.07984)（2026, arXiv）
   - 新建：[结构化解析](../papers/parsed/2026-arxiv-agentnas.md)；官方代码提供 `v1.0-reproducible` tag。
   - LLM 先搜索 seed，再合成带 module/glue/learning-rate slots 的有界空间，最后由 regularized evolution 搜索组合。
   - 与本仓库最直接的假设是：固定 macro scaffold，让 LLM 定义可验证 slots，再比较 random/evolution；但论文是单目标任务性能搜索，不是 quality/latency/memory/cost Pareto。

2. [Structuring Open-Ended NAS](https://arxiv.org/abs/2605.19247)（FairNAD，2026, arXiv）
   - 新建：[结构化解析](../papers/parsed/2026-arxiv-fairnad.md)。
   - 将设计知识组织为 operation、block/connectivity、network 层级，结合 fair idea sampling、Pareto-aware mutation、LLM iterative mutation 和 verifier loop。
   - 500 候选报告约 24.22–30.06 GPU-days/数据集；没有作者代码、完整 trace 或 LLM token/费用，不能只凭 accuracy 表作端到端效率结论。

3. [LLM-NAS: LLM-driven Hardware-Aware Neural Architecture Search](https://arxiv.org/abs/2510.01472)（2026, GECCO）
   - 新建：[结构化解析](../papers/parsed/2026-gecco-llm-nas.md)；GECCO 2026 官方录用页已核验。
   - 早期 OpenReview 标题 PEL-NAS 与当前 LLM-NAS 是同一 arXiv ID；当前方法按复杂度分区、维护分区 Pareto archive，并用历史规则库驱动 GPT-4.1 mutation/crossover。
   - HV/IGD、latency niches 和 120 calls 很值得作为直接对照；但 accuracy 主要来自 predictor、latency 来自 HW-NAS-Bench lookup，离线 predictor/benchmark 成本未纳入“3 分钟”口径。

## 已筛选、暂不入库

- [LLM-Driven AutoML for Cross-Lingual Handwritten OCR](https://arxiv.org/abs/2607.15509)：确实生成和训练真实 OCR 架构，但搜索对象、预算公平性和多目标协议较窄；作为 code-level AutoML 的后续候选。
- [Similarity-Guided Curriculum Fine-Tuning of LLMs for Neural Architecture Synthesis](https://arxiv.org/abs/2607.11591)：关注 LLM 架构代码生成成功率和接口修复，更接近 generator 训练而非完整 NAS policy；后续可用于 action validity 对照。
- [TacEvo](https://arxiv.org/abs/2606.30109)：LLM code mutation + MAP-Elites 的真实触觉架构搜索，和 diversity/efficiency 有关；待下一轮核对 20-seed 评估、代码与候选预算。
- [Bi-NAS](https://arxiv.org/abs/2607.01387)：NAS 搜索推荐解释模块，但 LLM 只用于生成自然语言解释，不指导神经架构搜索，排除出 LLM-guided NAS 主线。
- [ArchPilot](https://openreview.net/forum?id=6rEuy1CXQ1)：主要在 MLE-Bench 搜索/调试 ML engineering solution，搜索对象并非稳定定义的神经架构空间，继续作为 Agent 工作流对照而非 NAS 证据。
- 本轮未发现新的、直接针对 4–10 层 Conv1d Transformer 的 LLM-guided NAS 论文；现有新增工作的搜索空间分别是跨模态开放代码、视觉 backbone/cell 和 ViT。

## 重点结论与后续问题

- **搜索空间构造应成为独立变量。** AgentNAS 的 slotted synthesis、FairNAD 的分层知识树和 LLM-NAS 的 complexity niches 都在把开放式 LLM 设计变成可控空间；本仓库应比较它们对 validity、duplication、coverage 和 hypervolume 的独立贡献。
- **公平预算仍是主要缺口。** 三篇工作分别存在提前停止/recipe 联合搜索、24–30 GPU-days 与未量化 token、predictor/lookup 离线成本未计入的问题。后续实验必须统一候选、训练、GPU、LLM calls/tokens 和设备测量预算。
- **Pareto 证据强弱需分层。** LLM-NAS 报告 HV/IGD，但依赖 surrogate；FairNAD 用 Pareto parent sampling，却主要报告 accuracy；AgentNAS 只做单目标。当前项目应同时保留 surrogate 搜索轨迹与最终真实 quality/latency/memory 测量。
- **下一步优先级。** 先在 4–10 层 Conv1d Transformer 上做 `global vs slots vs niches` 的小预算协议；再解析 TacEvo，并核查 LLM-NAS predictor split、AgentNAS `v1.0-reproducible`、FairNAD 知识库和代码可用性。
- `quality_proxy` 与 `latency_proxy_ms` 仍只作为控制流占位符；本日报没有把它们或任何论文 surrogate 当作真实研究结论。
